# Skill: graph_builder

## Purpose
Maintain `knowledge/graph/{nodes.yaml, edges.yaml}` and produce `graph.json` for the website. Source of truth for graph topology (CLAUDE.md §8).

## When to Use
- After every object ingestion (article / tool / dataset / method / benchmark / model)
- When taxonomies update
- Before website rebuild

## Do Not Use When
- Only updating object content with no edge changes (still safe to run, but no diff expected)

## Inputs
- New or modified object YAMLs
- Manual edge additions described by user or pipeline

## Outputs
- `knowledge/graph/nodes.yaml` (appended)
- `knowledge/graph/edges.yaml` (appended)
- `knowledge/graph/graph.json` (regenerated by `scripts/python/build_graph.py`)

## Standard Workflow
1. For each new object, append a node entry: `{ id, type, label, aliases?, taxonomy_path? }`.
2. For each known relationship, append an edge: `{ from, to, type, evidence?, confidence? }`.
3. Verify edge `type` is in the allowed enum (see `schemas/graph.schema.yaml`).
4. Run `validate_schema.py` (cross-checks `from`/`to` exist in `nodes.yaml`).
5. Run `build_graph.py` to regenerate `graph.json` and reverse_index.
6. Run `check_orphans.py` and surface zero-edge nodes in the update report.

## Decision Rules
- **Versioning**: different versions get different node ids, joined via `uses_version` / `version_of` / `supersedes` (CLAUDE.md §9.2). Never collapse versions into one node.
- **Reverse links are NOT hand-written**: they are derived in `graph.json.reverse_index`. The `related_*` arrays in object YAML are convenience hints for humans only.
- **Missing-reference policy** (CLAUDE.md §11.6): never silently invent a stub node. Ask the user for each unresolved reference.
- Edge `evidence` should be a citation or a one-line rationale, not a paraphrase.

## Related Nodes
- skills: `local_graph_builder`, `taxonomy_updater`, `alphaxiv_blog_writer` (reads reverse_index for local-graph cards)
- scripts: `scripts/python/build_graph.py`, `scripts/python/check_orphans.py`

## Failure Modes
- Edge points to a node that doesn't exist → `validate_schema.py` warns; `build_graph.py` drops it and reports `n_edges_dropped_dangling`.
- Two nodes with the same id → ambiguous; resolve by renaming one and adding `aliases`.
- Cycles via `extends` or `supersedes` → not strictly invalid, but flag for review.

## Examples
- Adding UNI: append `model:uni` node; add edges `uni-2024 --releases_model--> uni`, `uni --version_of--> pathology-foundation-model` (if abstract method node exists), `uni --uses_dataset--> mass-100k` (if pretrain dataset has a node, else apply §11.6).
- Adding PANDA: append `dataset:panda` node; edges `panda --belongs_to--> prostate`, `panda --used_by_benchmark--> wsi-pfm-benchmark` (if exists).

## Validation Checklist
- [ ] All new nodes appended to `nodes.yaml`
- [ ] All new edges appended to `edges.yaml`
- [ ] `validate_schema.py` passes with zero errors
- [ ] `build_graph.py` reports zero dropped edges
- [ ] `check_orphans.py` shows no surprise orphans (or they are flagged in report)
